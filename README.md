Система аутентификации и авторизации, реализованная на FastAPI.

Позволяет выполнять CRUD-операции с пользователями, правами доступа, и товарами (демонстрационная сущность) с учетом прав доступа пользователя.

Аутентификация реализована с помощью JWT-токенов. JWT-токен нужно передавать в заголовке при каждом запросе.
Если токен неверный или истек, вернется ошибка с кодом 401.
Имеется рабочая авторизация - происходит сопоставление имеющихся у пользователя прав с теми, которые необходимы для доступа к ручке.
Если у пользователя недостаточно прав доступа, вернется ошибка 403.

Доступ к ресурсам настраивается гибко, возможно множество конфигураций. Требуемые права доступа прописываются в коде ручки.
На одну бизнес-сущность у пользователя может быть только одна сущность прав доступа, которая содержит настройки всех возможных операций. Это предотвращает конфликты прав доступа и создание лишних записей в БД.
Администратором можно считать пользователя, у которого есть все права. Администратор создается при запуске программы, если он еще не существует. Его почта - admin@admin.ru, пароль - admin.

Публичны следующие ручки:
- Регистрация (POST /users)
- Вход (POST /login)
- Просмотр товаров (GET /products)
- Просмотр конкретного товара (GET /products/{id})

Допустим, пользователь зашел на сайт интернет-магазина, и у него есть возможность посмотреть товары без регистрации.

Остальные ручки предполагают администрирование системы, поэтому к ним применяются ограничения.
- Получение списка пользователей (GET /users, GET /users/{id}) - необходимо право на чтение бизнес-сущности 'Пользователь'.
- Изменение пользователя (PATCH /users/{id}) - необходимо право на изменение бизнес-сущности 'Пользователь'.
- Удаление пользователя (DELETE /users/{id}) - необходимо право на удаление бизнес-сущности 'Пользователь'.
То же самое для других бизнес-сущностей.

Для доступа к ручке выхода из системы (POST /logout) необходимо пройти аутентификацию.

Схема базы данных следующая:

1. Таблица users.
Таблица пользователей.

Атрибуты:
- id: идентификатор пользователя
- name: имя пользователя
- surname: фамилия пользователя
- patronymic: отчество пользователя
- email: электронная почта пользователя
- password: пароль пользователя (хэш)
- is_active: флаг удаления аккаунта пользователя

2. Таблица permissions.
Таблица прав доступа.

Атрибуты:
- id: идентификатор права доступа
- name: наименование права доступа
- description: описание права доступа
- create: флаг разрешения на запись
- read: флаг разрешения на чтение
- update: флаг разрешения на изменение
- delete: флаг разрешения на удаление
- business_entity: бизнес-сущность, к которой применяются права доступа

3. Таблица user_permissions.
Связующая таблица между пользователями и правами доступа для связи многие-ко-многим.

Атрибуты:
- user_id: идентификатор пользователя
- permission_id: идентификатор права доступа

4. Таблица revoked_tokens.
Таблица токенов, которые были отозваны при выходе из системы.

Атрибуты:
- jti: идентификатор JWT-токена
